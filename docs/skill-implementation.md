# Agent Skill 구현 기록

[skill-spec.md](skill-spec.md)의 계획(P0–P2: 최소 기능)을 단계별로 구현한 기록. 단계마다 무엇을 했는지, 결정과 이유, 검증 방법, spec과 달라진 점을 남긴다.

## P0. 패키징·서버 수명주기 (2026-11-04)

### 한 일
- 코드를 skill 폴더로 이동: `server/` → `.agents/skills/web-excel/scripts/server/`, `static/` → `.agents/skills/web-excel/assets/web/`.
- `.claude/skills/web-excel` → `../../.agents/skills/web-excel` 심볼릭 링크(이 저장소를 연 Claude Code가 프로젝트 skill로 인식).
- 의존성 동봉: `scripts/_vendor/`에 openpyxl 3.1.5, et_xmlfile 2.0.0(MIT), xlrd 2.0.2, xlwt 1.3.0(BSD)과 라이선스. 약 2.3MB. (이후 변경: xlwt 제거, 이어서 Python 패키지 동봉 자체를 그만두고 `scripts/requirements.txt`로 설치 안내 — 맨 아래 항목 참고)
- `scripts/xl.py`: `serve`(분리 실행·재사용), `serve --foreground [--exit-with-parent]`, `status [--brief]`, `stop [--force]`, `launch-config`.
- 서버(`server/app.py`): 라우트 표 방식으로 재작성, 토큰 인증, `/api/health`, `/api/shutdown`, 활동 시각 기록.
- `SKILL.md`(이식판), `SKILL.claude-code.md`(Claude Code판), `references/troubleshooting.md`.
- `run.py`는 개발용 래퍼(`xl.py serve --foreground`)로 변경. 이전 다중 창 대체 경로였던 `/api/session`은 제거(P1에서 서버 경유 동기화로 대체).

### 결정과 이유
- **원본 위치 `.agents/skills/`**: Codex·VS Code·Cursor·Gemini CLI가 공통으로 읽는 경로(spec §2.1.1). Claude Code는 링크로 연결.
- **상태 파일 `<작업 경로>/.web-excel/server.json`**: 작업 경로마다 서버 하나. 임시 파일 + `os.replace`로 원자적 기록, 권한 0600, 폴더에 `.gitignore`(`*`)를 자동 생성해 토큰이 커밋되지 않게 함.
- **포트**: 8765부터 빈 포트를 찾음. 고정 포트만 쓰면 다른 작업 경로의 서버나 잔존 프로세스와 충돌.
- **인증**: CLI는 `X-WebExcel-Token` 헤더. 브라우저는 `/` 로드 시 받는 `HttpOnly; SameSite=Strict` 쿠키(+POST에는 기존 `X-WebExcel` 헤더). `/api/health`는 토큰 없이 `{ok, app}`만, 토큰이 있으면 pid·root까지 반환(`alive()`가 pid로 같은 서버인지 확인).
- **수명주기 자기방어**: 클라이언트·요청 없이 `--idle-timeout`(기본 3600초) 지나면 종료, `--exit-with-parent`면 부모 PID가 바뀔 때 종료(POSIX만; Windows는 미지원으로 둠).
- **분리 실행**: POSIX `start_new_session=True`, Windows `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW`. 로그는 `.web-excel/server.log`.
- **`SKILL.claude-code.md`를 패키지 안에 둠**: 검증기는 링크되지 않은 .md라고 경고만 한다(오류 아님). 이름이 `SKILL.md`가 아니라 "SKILL.md 2개" 오류에는 걸리지 않는다. 링크로 연결된 Claude Code에는 이식판 `SKILL.md`가 로드되며 그대로 동작한다.

### 검증
- `serve` → 새 서버 시작, 재실행 시 재사용, `status --brief`, 토큰 없는 `/api/info` 401, 쿠키로 200, `launch-config`가 기존 구성을 보존하며 엔트리 추가, `stop`.
- `--idle-timeout 3` → 약 3초 뒤 종료 로그 확인. Python 부모를 강제 종료 → `--exit-with-parent` 서버가 2초 안에 종료.
- 발견·수정한 버그: 없는 POST 경로로 요청이 오면 본문을 읽지 않아 같은 keep-alive 연결의 다음 요청이 깨짐 → 라우팅 전에 항상 본문을 읽도록 수정.
- `validate_skill.py --portable` 통과(오류 0, 경고 1: `SKILL.claude-code.md` 미링크). Python 왕복 5/5, 엔진 70/70, 브라우저 E2E 34/34.

### spec과 달라진 점
- `skills-ref validate`는 이 세션 네트워크에서 설치 불가로 아직 돌리지 못함(P6에서).
- Windows 분리 실행과 `--exit-with-parent`는 Linux에서만 검증.

## P1. 서버가 문서를 소유하는 동기화 (2026-11-04)

### 한 일
- `server/session.py`: `DocSession`(시트·셀·서식을 서버 메모리에 보관, 버전, op 로그 5,000개, 되돌리기용 이전 상태), `Registry`(열린 문서 목록), `Hub`(SSE 구독자 큐), 저장 전 백업.
- `server/docs_api.py`: `GET/POST /api/docs`, `GET /api/docs/{id}`·`/snapshot`, `POST /ops`·`/presence`·`/calc`·`/save`·`/undo`, `DELETE /api/docs/{id}`, 창당 이벤트 스트림 `GET /api/stream` + `POST /api/stream/subscribe|unsubscribe`.
- 브라우저: `js/docsync.js`(문서별 동기화 + 창 하나당 이벤트 스트림), `model.js`에 시트 JSON 변환·원격 op 적용(`applyRemote`)·좌표 변경 표시(`markStructural`), `app.js`의 열기/새로 만들기/저장/닫기/새 창을 서버 문서 기준으로 변경, 다른 클라이언트가 바꾼 셀을 노란색으로 잠깐 강조하고 상태 표시줄에 표시.
- 제거: `js/sync.js`(BroadcastChannel), `/api/open`·`/api/save`·`/api/new`(문서 API로 대체).

### op 형식
`setCells {sheet, cells:[[r,c,cell|null]]}`, `setSheetMeta {sheet, meta}`, `sheets {order, add}`, `setWorkbook {props}`. 시트는 이름이 아닌 id로 지칭. 브라우저는 실행 취소 기록(트랜잭션 항목)을 그대로 이 op들로 바꿔 보낸다(변경 후 상태를 보내므로 서버는 의미를 해석할 필요가 없다).

### 결정과 이유
- **같은 셀 충돌은 나중 도착 우선(LWW)**: 서버가 순서를 정하므로 타임스탬프가 필요 없다(Figma 방식, spec [4]). 브라우저는 자기 변경의 echo가 SSE로 돌아올 때까지 그 셀을 "대기 중"으로 두고, 그 사이 도착한 남의 변경은 그 셀에 적용하지 않는다. 서버는 내 변경을 나중에 적용하므로 결과가 서버와 같아진다.
- **좌표를 바꾸는 변경은 거절 후 재동기화**: 행/열 삽입·삭제, 정렬, 시트 이름 변경, 셀 이동, 중복 제거, 시트 구조 변경이 해당. 기준 버전 이후 다른 클라이언트의 변경이 있으면 409 → 브라우저가 스냅샷을 다시 받고 알림. spec의 MVP 규칙 그대로(P3에서 좌표 변환으로 개선 예정).
- **창당 이벤트 스트림 1개**: 처음엔 문서마다 EventSource를 열었는데, 두 번째 창의 요청이 멈췄다. 브라우저는 HTTP/1.1에서 호스트당 연결을 약 6개로 제한하고 이 한도를 탭 전체가 공유하기 때문. 창마다 `/api/stream` 하나를 열고 문서는 POST로 구독하도록 바꿨다. 구독 시 재전송(since 이후 op)과 구독 등록을 문서 잠금 안에서 함께 해 빠지거나 중복되는 이벤트가 없게 했다.
- **브라우저가 계산값을 보고**: 계산 엔진이 JS라 서버는 수식 결과를 모른다. 열린 창이 재계산 후 바뀐 수식 결과만 `/calc`로 보내고, 서버는 버전과 함께 저장한다(P2의 `read`가 사용, 저장 시 xls 캐시 값으로도 사용).
- **저장 안전장치**: 같은 경로에 덮어쓸 때 열 때의 (mtime, size)와 다르면 409(다른 프로그램이 저장). 덮어쓰기 전 `.web-excel/backups/`에 사본(DRM 정책상 사본 금지면 `backup:false`). 유휴 종료 시 저장 안 된 문서는 `.web-excel/recovery/`에 JSON으로 남김.
- **에이전트 변경 되돌리기**: 각 batch에 이전 상태를 기록해 `POST /undo {batchId}`로 되돌림. 이후 같은 셀이 바뀌었으면 409(force로 강제).
- **창을 닫아도 문서는 서버에 남음**: 그래서 "저장 안 하고 나가기" 경고(beforeunload)를 없앴다. 탭의 × 는 서버 문서를 닫는다(저장 안 됐으면 확인).

### 검증
- `tests/sync.e2e.cjs` 11개 통과: 에이전트 op가 브라우저에 반영·강조, 브라우저 입력이 서버 스냅샷에 반영, 계산값 보고 버전, 같은 셀 동시 쓰기 수렴, 오래된 기준 버전의 좌표 변경 409, 두 번째 창 실시간 반영, 에이전트가 연 파일이 탭으로 표시, batch 되돌리기.
- 기존 `tests/e2e.cjs` 34개(열기·필터·정렬·차트·저장·재열기·xls·다중 창 포함), Python 왕복 5개, 엔진 70개 통과.

### spec과 달라진 점
- 문서별 SSE(`/api/docs/{id}/events`) 대신 창당 스트림을 기본으로 했다(문서별 엔드포인트는 CLI용으로 남김).
- 다른 클라이언트의 선택 영역 표시는 아직 하지 않음(서버에 presence는 저장, CLI `selection`에서 사용 예정).

## P2. 에이전트 CLI (2026-11-04)

### 한 일
- `server/agent_api.py`: `POST /api/docs/{id}/edit`(사람 수준의 편집 → 상태 op 변환, 한 batch), `GET /range`, `/describe`, `/changes`, `/selection`, 수식 결과 최신화(`ensure_calc`).
- `server/a1.py`: A1 참조 파싱, 시트 이름 변경 시 다른 시트 수식·차트 범위·정의된 이름 재작성.
- `scripts/calc/worker.mjs`: 브라우저가 쓰는 엔진(`model.js`)을 Node에서 그대로 돌려 수식 결과 계산.
- `scripts/cli_docs.py`: `ls, open, new, docs, describe, read, write, fill, clear, format, merge, unmerge, width, height, hide, unhide, freeze, filter, sheet, chart, apply, changes, selection, undo, save, close` (+ 기존 서버 명령).
- `SKILL.md` 본문 완성(작업 순서·명령표·값 해석 규칙·계산·종료 코드, 85줄·약 1.7k 토큰), `references/cli.md`·`edits.md`, `tools/build_claude_code_skill.py`로 `SKILL.claude-code.md` 생성.

### 결정과 이유
- **편집은 서버에서 op로 변환**: CLI는 얇게 두고(stdlib만), 범위 해석·값 해석·서식 병합은 서버가 한다. 결과는 P1과 같은 상태 op라서 브라우저에 그대로 실시간 반영되고 batch 단위로 되돌릴 수 있다.
- **값은 Excel 입력처럼 해석**: `=`는 수식, `2026-03-15`는 날짜(일련번호 + yyyy-mm-dd 서식), `15%`, `1,234`, `₩1,000`, `TRUE`. `'`로 시작하거나 `--raw`면 문자열 그대로. 에이전트가 날짜를 문자열로 넣는 실수를 막기 위함.
- **읽기 결과는 사람이 읽는 형태**: 날짜 서식 숫자는 ISO 문자열, 실수는 15자리 유효숫자(`110.39999999999999` → `110.4`), 전체 열 범위는 사용 범위로 자르고 기본 200행에서 끊어 다음 범위를 알려 준다(토큰 절약).
- **채우기(fill)는 상대 참조 이동**: 한 수식을 범위에 채우면 행/열마다 상대 참조를 옮긴다(Python 정규식 구현, 문자열·따옴표 시트 이름은 건드리지 않음). 전체 참조 재작성(행 삽입 등)은 여전히 P3.
- **수식 결과의 출처 3단계**: ① 미리보기 창이 보고한 값(최대 2초 대기) ② 없으면 Node로 같은 엔진 실행 ③ 둘 다 없으면 `stale`로 표시하고 파일의 마지막 계산값 사용. 응답에 `calc.status/source`를 함께 준다.
- **문서 지정**: 문서가 하나면 `--doc` 생략. 여러 개면 id·이름·경로로 지정하고, 모호하면 목록과 함께 exit 2.
- **상대 경로는 작업 경로 기준**: 에이전트의 셸 위치와 서버 root가 다를 수 있어서 `open`, `save --as`, `ls`, `apply`, `--tsv` 모두 root 기준으로 해석.
- **종료 코드**: 0 성공, 2 사용법, 3 서버 없음, 4 충돌(409), 5 파일·DRM·시트 오류 — 에이전트가 다음 행동을 고르기 쉽게.

### 검증
- `tests/agent_cli.test.py` 34개 통과: 기동·재사용, 열기, describe, 읽기(날짜 ISO), fill의 상대 참조 이동, 브라우저 없이 Node 계산, Excel식 값 해석, 서식·되돌리기, 열 너비, 차트, 시트 이름 변경 시 다른 시트 수식 갱신, 교차 시트 수식, `edits.md` 예제 그대로 적용, 변경 이력, 백업 저장 후 openpyxl로 시트 이름·수식·차트·열 너비·날짜 확인, 오류 종료 코드, 저장 안 된 상태의 stop 거부.
- 기존 스위트 모두 통과: Python 왕복 5, 엔진 70, 브라우저 E2E 34, 동기화 11.
- 테스트로 찾아 고친 버그: (1) 상대 경로를 CLI 위치 기준으로 해석, (2) 빈 시트에 한 batch로 값을 쓰고 서식·차트를 만들면 앞서 쓴 셀을 못 보고 범위를 A1로 잘라 버림, (3) 포트 검사에 `SO_REUSEADDR`가 없어 TIME_WAIT 포트를 사용 중으로 판단.
- `validate_skill.py --portable` 통과(경고 1: `SKILL.claude-code.md` 미링크, 의도된 것).

### spec과 달라진 점·남은 것
- 행/열 삽입·삭제와 정렬은 에이전트 CLI에 아직 없음(P3: 참조 재작성 Python 포팅 필요). 미리보기에서 사용자는 할 수 있음.

## P3. 구조 변경(행/열 삽입·삭제, 정렬)과 충돌 좌표 변환 (2026-11-04)

### 한 일
- `server/refs.py`: 브라우저 `formula.js`의 토큰화·참조 재작성(`translate`, `adjust`, 시트 이름 변경)을 Python으로 그대로 이식. `agent_api.py`의 정규식 기반 구현을 이것으로 교체.

- 충돌 규칙 개선(`session.apply`): 오래된 기준 버전의 **셀 편집**이 다른 클라이언트의 행/열 삽입·삭제 뒤에 도착하면, 거절하지 않고 그 이동만큼 좌표와 수식을 옮겨 적용. 지워진 행/열에 쓴 값은 버림. 정렬·시트 삭제 뒤이거나, 이동된 시트의 속성(열 너비 등)을 통째로 바꾸는 batch는 여전히 409.
- 브라우저: 행/열 삽입·삭제 batch에 이동 정보(`shifts`)를 함께 보냄. 내 변경이 서버에서 옮겨졌거나, 내 변경이 대기 중일 때 원격 구조 변경이 오면 대기분이 다 확인된 뒤 조용히 다시 불러옴(편집 중이면 끝날 때까지 미룸).
- 구조 변경 batch 되돌리기: 반대 방향 이동 정보로 기록해 이후 충돌 변환에도 쓰임.

### 결정과 이유
- **재작성기를 새로 짜지 않고 이식**: 같은 수식이 브라우저와 서버에서 다르게 바뀌면 동기화가 깨진다. JS의 토큰화 순서(문자열 → 오류 → 숫자 → 참조 → 식별자)와 "알 수 없는 문자면 수식을 그대로 둔다"는 동작까지 맞췄다.
- **셀 편집만 변환**: 셀 좌표는 이동 규칙이 명확하지만, 시트 속성 op는 상태 전체를 보내므로 변환하면 이동 결과를 덮어쓴다. 정렬은 행 순서를 섞으므로 "같은 내용의 새 위치"를 정할 수 없다. 이 경우만 거절하고 다시 불러오게 했다.
- **구조 변경마다 별도 batch**: Excel에서 행 삽입 뒤 입력하는 것처럼, 뒤따르는 편집은 삽입 후 좌표로 쓰는 것이 자연스럽다. 되돌리기도 단계별로 가능.

## 표가 A1에서 시작하지 않을 때 (2026-11-04)

### 확인 방법
제목(B2, B2:F2 병합), 빈 행, 머리글 C5:F5, 데이터 C6:F12, 바로 아래 합계 행 C13(`=SUM(D6:D12)` 등), 옆에 메모(H5)가 있는 파일(`samples/offset.xlsx`)로 UI와 에이전트 동작을 모두 확인했다.

### 발견한 문제
- **UI**: 셀 하나에서 Ctrl+Shift+L을 누르면 Excel처럼 붙어 있는 영역(C5:F13)을 잡는데, 합계 행까지 필터 범위에 들어갔다. 이어서 정렬하면 합계 행이 데이터 사이로 섞이고 `=SUM(D6:D12)`가 `#REF!`로 깨졌다.
- **UI**: 영역 확장 루프가 최대 200번만 돌아, 200행이 넘는 표는 셀 하나에서 필터/정렬할 때 잘릴 수 있었다.
- **에이전트**: `filter D7`(셀 하나)은 D7:D8, `filter C:F`(열 전체)는 제목·빈 행을 포함한 C1:F13이 됐고, `sort D7`은 아무것도 하지 않았다. `describe`는 사용 범위를 A1부터로, 제목 행을 머리글로 보고했다.

### 고친 것
- 영역 판정을 UI(`filter.js`)와 서버(`server/region.py`)에 같은 규칙으로 구현: 붙어 있는 데이터 영역을 찾고(빈 행·열에서 끊김), 끝의 **합계 행**은 필터·정렬·차트·중복 제거 대상에서 뺀다. 합계 행 판정은 첫 열 텍스트가 합계/총계/소계/평균/Total 등이거나, 위쪽 행들을 SUM·SUBTOTAL·AVERAGE·COUNT·MAX·MIN으로 묶는 수식이 있는 행.
- 에이전트 명령에 **셀 하나나 열/행 전체**를 주면 그 위치의 표로 확장. 여러 셀 범위를 명시하면(예: `filter C5:F13`) 합계 행 포함이라도 그대로 존중.
- 필터가 켜진 범위 안에서 정렬하면 필터 범위의 표(합계 제외, 머리글 유지)를 정렬. 필터 "다시 적용"은 아래에 추가된 행은 포함하되 합계 행은 포함하지 않음.
- `describe`: 사용 범위를 실제 첫 셀부터 보고하고, 시트의 **표 목록**(범위·머리글 행·합계 행)을 따로 보여 준다. 머리글과 열 유형은 가장 큰 표 기준.
- Ctrl+A는 Excel과 같이 합계 행을 포함한 영역 전체를 선택(바꾸지 않음).

### 검증

## 저장한 수식이 Excel에서 그대로 열리는지 (2026-11-04)

### 확인 방법
`tests/excel_compat.test.py`: 수식 229개(함수 약 170종, 날짜 기준 경계 45개 포함)를 앱과 같은 저장 경로(`write_workbook`)로 xlsx에 쓰고
1. 저장된 수식 텍스트에 OOXML 접두사(`_xlfn.`, `_xlpm.`)가 붙었는지,
2. 계산하지 않는 읽기 도구(openpyxl `data_only`)가 결과를 보는지,
3. 캐시 값을 뺀 사본을 LibreOffice 24.2로 열어 다시 계산한 값이 우리 엔진과 같은지(상대오차 1e-12) 본다.
LibreOffice는 xlsx를 열 때 기본으로 캐시 값을 그대로 쓰므로, 캐시가 있는 파일로는 재계산 비교가 되지 않는다.

| DAYS360에 method 인자 없음, 2월 말 처리 누락 | US/EU 방식 결과 다름 | US(NASD)·EU 방식 구현 |

### 결과
- 접두사 30/30, 캐시 값 229/229, 계산 없는 읽기 229/229.
- LibreOffice 재계산 225/229 일치. 나머지 4개(XLOOKUP 2, XMATCH, LET)는 LibreOffice 24.2에 없는 함수라 비교 불가(24.8부터 지원).
- `"a"&1&TRUE`는 Excel이 `a1TRUE`, LibreOffice가 `a11`로 서로 달라 대조에서 뺐다(우리는 Excel과 같음).

### 남은 한계
- 동적 배열(FILTER, SORT, UNIQUE, SEQUENCE의 넘침)은 Excel의 동적 배열 메타데이터(`metadata.xml`, `cm` 속성)를 쓰지 않아 Excel에서 `@`가 붙은 단일 값 수식으로 보일 수 있다.

## 계산할 수 없는 함수가 있는 파일 (2026-11-04)

### 요구
파일을 열 때 경고하고, 그 셀을 고치지 않았으면 저장할 때 원래대로 되돌려 저장.

### 전에는 어땠나
- 경고 없음. 셀은 파일의 캐시 값을 보여 줬다(엔진의 #NAME? 대체). 단, 파서가 못 읽는 문법(`LAMBDA(x,x*2)(A1)`)은 대체 없이 #NAME?.
- 저장 시 `_xlfn.`을 모두 떼고 이 앱이 아는 함수에만 다시 붙여서, 모르는 신규 함수(`_xlfn.NEWFUNC`)는 접두사를 잃고 Excel에서 #NAME?이 됐다.
- 이런 셀에서 F2 → Enter를 누르면 편집기가 "수식에 문제가 있습니다"로 커밋을 거부해 빠져나올 수 없었다.

### 구현
| 부분 | 내용 |
|---|---|
| 감지 (`formula_compat.unsupported_functions`) | 수식에서 호출하는 함수 중 엔진에 없는 것. 엔진 목록은 `engine.js`의 `def(...)` 표에서 읽고, 테스트가 엔진의 `FUNCTION_NAMES`(218개)와 같은지 확인. `_xludf.`(VBA)·`_xll.`(추가 기능)도 표시 |
| 원본 보존 (`fo`) | 읽을 때 지원 안 되는 함수가 있거나 접두사 복원이 원본과 다르면 파일의 수식 텍스트를 셀의 `fo`에 둔다. 서버·브라우저·에이전트 명령 모두 셀을 복사해 고치므로 함께 따라간다 |
| 저장 규칙 | `strip_prefixes(fo) == f`(수식이 그대로)면 `fo`를 그대로 쓴다. 다르면 일반 경로 + 파일에서 본 접두사 표(`prefix_map`)로 모르는 함수의 `_xlfn.`도 유지. 고친 미지원 수식은 결과를 `#NAME?`으로 저장하지 않고 비워 Excel이 계산하게 한다 |
| 결과 값 | 엔진이 파싱 오류일 때도 파일의 캐시 값으로 대체 |
| 경고 | 열 때 경고(CLI `open`, 미리보기 토스트), `describe`에 셀 목록과 원본 유지 여부(`kept`), 미리보기에서 그런 셀의 수식을 바꾸면 한 번 경고 |
| 편집기 | 바뀌지 않은 텍스트는 문법 검사 없이 커밋(아무 변경 없음) |

판단 기준을 셀 위치가 아니라 "수식 텍스트가 같은가"로 둔 이유: 행 삽입 등으로 참조가 바뀌면 원본은 더 이상 맞지 않고, 위치가 바뀌어도 텍스트가 같으면 원본이 여전히 맞기 때문.

### 검증
- `tests/preserve_formulas.test.py` (에이전트 경로, 13개): LAMBDA 호출·TEXTSPLIT·VBA 함수·모르는 `_xlfn.` 함수가 든 파일 → 경고, describe 목록, 캐시 값 표시, 서식만 바꾼 셀·안 건드린 셀은 저장 XML의 `<f>`·`<v>`가 원본과 바이트 단위로 같음, 고친 셀은 접두사 유지·`#NAME?` 미저장, 지원 함수는 정상 재계산.
- `tests/preserve.e2e.cjs` (미리보기, 10개): 경고 토스트, F2+Enter가 편집기를 빠져나오고 아무것도 바꾸지 않음, 수식 수정 경고, 저장 결과.

### 한계
- 미지원 셀의 결과는 파일을 연 시점 값으로 고정된다. 그 셀이 참조하는 값을 바꾸면 화면 값은 갱신되지 않고(Excel에서 열면 재계산), 경고 문구에 이를 적었다.
- xls는 xlrd가 수식 텍스트를 주지 않아 대상이 아니다(열 때 이미 "수식을 값으로 읽는다" 경고가 나온다).
- openpyxl이 읽지 않는 셀 속성(동적 배열의 `cm`, 데이터 표 `t="dataTable"`)은 이 방식으로도 복원되지 않는다.

## xls는 읽기 전용, xlwt 제거 (2026-11-04)

### 이유
1. 라이선스: xlwt의 `Utils.py` 일부가 LGPL-2.1+이고 pyExcelerator 부분에 광고 조항이 있다. 제거하면 동봉 코드는 MIT·BSD·PSF만 남는다.
2. 데이터 보존: xlrd는 xls의 수식 텍스트를 주지 않는다. 열린 xls를 xls로 다시 저장하면 원본의 수식이 모두 값으로 바뀌었다(차트·자동 필터도 사라짐). xlsx로 따로 저장하면 원본이 그대로 남는다.
3. 코드·테스트 단순화(xls 쓰기 경로, BIFF 수식 캐시 패치 제거).

### 동작
- xls를 열면 "읽기만 하고 저장하면 같은 이름의 .xlsx"라는 경고.
- 저장: `report.xls` → `report.xlsx`(서버 `xlsx_target`; 브라우저도 미리 이름을 바꿔 확인 창에 실제 이름 표시). `report.xlsx`가 이미 있으면 덮어쓰기 확인(409). 저장 후 문서는 .xlsx를 가리킨다.
- `--as x.xls`, `--format xls`도 .xlsx로 저장(CLI `--format`에서는 xls 선택지 제거). 저장 대화상자에서 xls 형식 제거.
- `write_workbook`은 xls 대상을 거부(400) — 안전망.

### 라이선스 점검 중 보완
xlrd의 두 번째 라이선스(David Giffin 부분)에도 광고 조항이 있어 `THIRD_PARTY_NOTICES.md`에 고지 문구를 넣었다(이전 정리에서 누락).

### 검증
`test_roundtrip`(xls 읽기, xls 쓰기 거부, 대상 변환), `e2e.cjs`(xls 열기 → 편집 → Ctrl+S → 옆에 .xlsx 생성, 원본 xls 바이트 동일, 문서 이름 .xlsx로 변경).

1. **다른 사이트의 iframe 안에 띄우는 미리보기**: VS Code Simple Browser(웹뷰 안의 `iframe.src`), Tauri 앱(앱 페이지가 `http(s)://tauri.localhost` 또는 `tauri://localhost`). `localhost` 페이지는 cross-site 문맥이라 Strict 쿠키가 저장·전송되지 않는다. `SameSite=None`도 WKWebView(ITP)나 서드파티 쿠키 차단에서 막힌다. 새로 고쳐도 그대로라 이번 증상과 일치.
2. 쿠키는 포트를 구분하지 않아 같은 PC의 다른 서버 페이지를 열면 먼저 연 창이 401.
3. 서버가 다시 시작되면 토큰이 새로 생겨 열려 있던 창이 401(새로 고치면 해결).

### 변경
- `serve`/`status`가 `http://localhost:PORT/#t=TOKEN`을 출력(`server.json`의 `url`, 토큰 없는 주소는 `base_url`). `#` 뒤는 서버로 전송되지 않는다.
- 페이지(`api.js`): 주소의 토큰을 `sessionStorage`에 보관하고 주소창에서 지운 뒤(저장이 막히면 지우지 않음), 모든 API 요청에 `X-WebExcel-Token` 헤더. 새 창(`window.open`)에도 `#t=`를 붙인다.
- 이벤트 스트림: `EventSource`는 헤더를 못 보내므로 `POST /api/stream/ticket`으로 1회용 티켓(60초)을 받아 `?ticket=`으로 연결. 로그에는 `ticket=***`로 남김.
- 쿠키는 최상위 탭(토큰 없이 연 경우, Claude Code 데스크톱 `launch.json` 미리보기)을 위해 유지하되 이름을 `wx_token_<포트>`로.

- 401 응답에 이유(`no-credentials`, `token-mismatch`, `cookie-mismatch`)와 안내, 서버 로그에 `reason=`과 `sec-fetch-site=`. 페이지는 401을 "연결할 수 없음" 대신 토큰 안내로 표시.
- SKILL.md: 사용자에게 `#t=…`까지 포함한 주소를 줄 것. troubleshooting에 401 항목.

## 미리보기에 어떤 문서를 보여 줄지 (2026-11-04)

### 증상
새로 고치면 열려 있던 파일 탭이 닫힌 것처럼 보이고, 에이전트가 `goto`를 해야 보였다.

### 재현으로 찾은 원인
1. 이미 열린 파일을 `xl.py open`으로 다시 열면 서버가 기존 문서를 돌려줄 뿐 미리보기에 알리지 않아 화면이 바뀌지 않았다.
2. 새로 고치면 서버 목록의 첫 문서(대개 빈 "통합 문서1")를 보여 줬다.
3. 빈 서버에서 미리보기를 열면 만든 빈 "통합 문서1"이 에이전트가 파일을 연 뒤에도 남아 2와 겹쳤다.
4. 마지막 탭을 잃은 창마다 서버에 빈 문서를 하나씩 만들었고, 다른 창은 그 문서로 화면이 바뀌었다.

### 변경
- **연 주체**: 'opened' 알림에 `by`(agent/user)와 `client`. CLI의 `open`/`new`는 `actor: agent`. 에이전트가 연 문서는 모든 창이 보여 주고, 다른 창의 사용자가 연 문서는 배경 탭.
- **다시 열기**: 에이전트가 이미 열린 파일을 `open`하면 서버가 'focus' 알림 → 모든 창이 그 문서를 보여 줌.
- **입력 보호**: 사용자가 셀을 편집 중이면 화면을 바꾸지 않고 탭에 표시만(상태 표시줄 안내).
- **처음 보여 줄 문서**: `?doc=` → 이 창이 새로 고치기 전에 보던 문서(`sessionStorage`) → 서버의 `focusedAt`(열기·다시 열기·goto·사용자 선택 변경 때 갱신)이 가장 최근인 문서.
- **빈 통합 문서 자동 생성 제거**: 열린 문서가 없으면 시작 화면("에이전트가 파일을 열면 여기에 자동으로 표시됩니다", [새 통합 문서] [열기…]). 문서가 없을 때는 명령과 단축키가 새로 만들기·열기·도움말만 동작.
- **배경 변경 표시**: 화면에 없는 문서를 에이전트나 다른 창이 바꾸면 탭에 하늘색 점, 그 탭을 열면 사라짐.

### 검증 중 찾은 버그
처음 보여 줄 문서를 고를 때 "이 창이 보던 문서" 값을 문서를 붙인 뒤에 읽어, 첫 문서 활성화가 그 값을 덮어써 새 창이 늘 첫 문서를 보여 줬다. 붙이기 전에 읽도록 수정(새 창 테스트로 발견).

### 검증
`tests/focus.e2e.cjs`(19개, 서버를 스스로 띄움): 빈 서버 → 시작 화면·서버에 문서 없음, 에이전트 open → 표시(빈 문서 없음), 다시 open → 표시, 입력 중 → 화면 유지·입력 보존·탭 표시, 배경 변경 표시·해제, 새로 고침 → 보던 문서, 새 창 → 최근 문서, 다른 창의 새 문서 → 배경 탭, 모두 닫기 → 시작 화면·서버에 빈 문서 안 생김, 시작 화면에서 키 입력 무해. e2e에 시작 화면 3개. 기존 테스트는 빈 서버에서 문서를 먼저 만들도록 수정, 전체 2회 통과.

`chart ls`에는 차트가 보이는데 `chart set ID …` / `chart rm ID`가 가끔 404.

### 원인 (재현)
`chart ls`는 모든 시트의 차트를 나열하지만, `set`/`rm`은 `--sheet`가 없으면 **활성 시트에서만** 찾았다. 서버의 활성 시트는 파일에 저장된 값(시트 추가·이동 때만 바뀜)이고 미리보기에서 시트를 바꿔도 달라지지 않는다. 그래서 그 시트가 아닌 곳의 차트는 항상 404였다. "가끔"은 차트가 어느 시트에 있느냐의 차이.

같이 발견: `chart add --at '비중!E2'`처럼 위치에 시트를 붙이면 `ValueError`가 그대로 올라와 HTTP 500.

### 수정
- `find_chart()`: id로 찾을 때는 모든 시트를 검색(id는 통합 문서 안에서 고유), `--sheet`는 검색 범위만 좁힘. 못 찾으면 어디서 찾았는지 알려 주는 404. 검색은 읽기만 하고 찾은 시트만 변경 대상으로 등록(검색한 모든 시트에 빈 변경이 생기지 않게).
- `--at`에 시트 허용: `chart add --at '비중!E2'`는 그 시트에 만들고, `chart set ID --at '매출!K2'`는 그 시트로 옮김. 잘못된 위치는 400과 이유, `--sheet`와 `--at`의 시트가 다르면 400.

### 검증
`tests/chart_ids.test.py`(12개): 다른 시트 차트의 set(--data 포함)/rm, 변경이 그 시트에만 기록되는지, `--sheet` 한정, 없는 id, `--at '시트!셀'`로 추가, 잘못된 `--at`, 시트 간 이동, 저장 결과. 수정 전 코드로는 첫 검사부터 404.

### 차트 id 수명 (같은 날, 최소 조치)
차트 id는 파일에 저장되지 않고 불러올 때마다 무작위로 붙는다. 같은 세션에서는 편집·저장해도 유지되지만, 닫았다 다시 열거나 서버가 재시작되면(사용이 없으면 1시간 뒤 스스로 종료) 바뀐다(실측). 파일에 id를 기록하는 방법(drawing `cNvPr name`)이나 시트+순번·제목 지정도 검토했으나, 이번에는 안내만 한다: SKILL.md 명령표·cli.md·troubleshooting에 "`chart set/rm` 전에 `chart ls`", 404 메시지에 "id는 다시 열기·재시작 때 바뀜, `chart ls`로 확인".

## 차트 스타일 통일 (2026-11-05)

### 한 계열 차트의 varyColors (같은 PR)
**증상**(사용자, Excel): "항목 / 값" 표로 만든 막대 차트가 미리보기에서는 한 색·범례 "값"인데, Excel에서는 막대마다 다른 색이고 범례에 항목 이름("행 수", "층 수 평균" …)이 나옴.
**원인**: 저장한 차트에 `<c:varyColors>`가 없었다(openpyxl 기본값 `None` = 기록 안 함). Excel은 이 요소가 없으면 "요소마다 다른 색"을 켠 것으로 그린다. 계열이 하나면 막대마다 색이 달라지고 범례가 항목 목록이 된다. LibreOffice는 없을 때 꺼짐으로 그려서 이 차이를 재현하지 못한다(확인).
**수정**:
- 저장: `varyColors`를 항상 기록. 원형은 1(원본이 0이면 0), 그 밖의 새 차트는 0, 원본 차트를 다시 만들 때는 원본 값 유지.
- 읽기: 모든 차트의 `varyColors`를 모델에 담음. 요소가 없으면 Excel처럼 켜짐.
- 미리보기: 한 계열이고 켜져 있으면 막대마다 테마 색, 범례에 항목 목록.
- `xl.py chart set ID --vary-colors on|off`로 바꿀 수 있음(이전 버전이 저장해 요소가 없는 차트를 한 색으로 되돌릴 때).
**검증**: `chart_style.test.py`에 4개(새 막대 0, 원형 1, 없는 요소 = 켜짐으로 읽기, `--vary-colors off`), `chart_style.e2e.cjs`에 2개(꺼짐: 한 색·계열 이름 범례, 켜짐: 막대별 색·항목 범례).

## 차트 데이터 범위 표시 (2026-11-05)
**요청**: 차트를 선택했을 때 차트가 쓰는 데이터 범위(이름·X·Y)가 어떻게 설정되었는지 보기.
**구현** (Excel의 범위 강조와 같은 색 구분):
- 격자(`grid.js` `chartRanges`): 선택한 차트의 계열 이름 셀은 초록(#008000), X(항목, 분산형은 X 값)는 보라(#7030A0), Y(값)는 파랑(#0070C0) 테두리와 옅은 채우기. 여러 계열이 같은 항목 범위를 쓰면 한 번만 그린다(채우기가 겹쳐 진해지지 않게).
- 패널(`charts.js` `showRanges`): 차트 바로 아래에 계열별로 이름(셀 값)·종류(혼합 차트의 꺾은선 등)·각 범위 참조. 행을 클릭하면 그 계열만 밝게, 다시 클릭하면 전체. 다른 시트를 가리키는 범위는 안내 문구.
- 에이전트: `describe`의 차트 항목에 `series: [{name, nameRef, x, y, type}]`, `xl.py chart ls`가 계열마다 `계열 n (종류): 이름 … X … Y …`를 출력.
- 주의: `grid.draw()`가 `charts.layout()`을 부르므로, 테두리 목록이 바뀔 때만 다시 그리도록 했다(처음 구현은 선택 중 매 프레임 다시 그림 — 테스트로 확인 후 수정).
**검증**: `tests/chart_ranges.e2e.cjs` 12개(`chart ls` 출력, 색·범위, 항목 범위 중복 없음, 패널 이름·참조, 선택 중 다시 그리기 없음, 계열 강조 켜기/끄기, 선택 해제, 원형). 화면: `docs/chart-ranges-preview.png`. 전체 Python·e2e 테스트 통과.

### 행/열 전환 (같은 PR)
**요청**: "축 반전" → Excel의 '행/열 전환'(계열과 항목(X)을 맞바꿈)으로 확인.
**규칙**: 데이터 범위를 다시 추측하지 않고 계열의 참조만 바꾼다.
- 계열 값이 같은 크기의 열(또는 행)로 나란히 붙어 있어야 한다(한 표). 그러면 값 블록의 각 행(열)이 새 계열이 된다.
- 예전 X(항목) 셀 하나하나가 새 계열의 이름이 된다. 예전 계열 이름 셀들이 한 줄로 붙어 있으면 그 범위가 새 X가 된다.
- X가 없는 계열은 첫 계열의 X를 함께 쓴다(Excel과 같음; 혼합 차트의 꺾은선 계열이 이런 경우가 많음).
- 두 번 전환하면 원래 참조로 돌아온다.
- 안 되는 경우는 이유를 알린다: 계열이 다른 시트에 있음, 값 범위가 떨어져 있음, 계열마다 X가 다름, 길이가 맞지 않음. 분산형은 X·Y가 짝이라 막는다.
- 계열별 종류(혼합 차트의 꺾은선)와 계열별 색은 넘어가지 않는다(계열 수와 의미가 바뀌므로).
**구현**: `charts.js` `ChartLayer.switchRowCol`(UI: 차트 오른쪽 클릭 '행/열 전환', 범위 패널의 '⇄ 행/열 전환' 버튼), `agent_more.py` `switch_row_col`(`chartUpdate`의 `switchRowCol`, CLI `chart set ID --switch`). 두 구현이 같은 결과를 내는지 테스트로 확인.
**검증**: `chart_ranges.e2e.cjs`에 5개 추가(UI 전환 결과, 테두리 갱신, 서버가 보는 결과, 에이전트로 되돌리기, JS·Python 6개 사례 일치 — 오류 사례 포함). 저장한 xlsx에 6개 계열로 기록됨을 확인. 화면: `docs/chart-switch-preview.png`.

## 분산형 차트 검토·수정 (2026-11-05)

2. **X가 텍스트이면 미리보기에서 점이 사라짐**
   - 원인: 텍스트 X가 `null`이 되어 Chart.js가 점을 건너뜀.
   - 수정: X 범위에 텍스트가 하나라도 있으면 Excel처럼 X를 1, 2, 3…으로 그림.
3. **저장 파일에 `scatterStyle` 누락**
   - 원인: ECMA-376의 `CT_ScatterChart`에서 필수 요소인데, openpyxl 기본값(None)이라 기록되지 않았다.
   - 수정: Excel이 '분산형'에 쓰는 `lineMarker` 값을 기록. 계열 선은 noFill이므로 표식만 보인다.
4. **축 위치가 모두 왼쪽으로 기록됨**
   - 원인: openpyxl이 모든 축을 `axPos="l"`로 기록한다. 막대·꺾은선도 마찬가지였다.
   - 수정: `chart_style.style_axes`에서 항목/X축은 아래(`b`), 값축은 왼쪽(`l`)으로 기록. 가로 막대는 반대.

**검증**:
- `tests/scatter.test.py` 8개: 에이전트 X 열 처리, `scatterStyle`, 표식만, 분산형·세로 막대·가로 막대의 축 위치, LibreOffice로 열기. 수정 전 코드에서는 5개가 실패함을 확인했다.

- 전체 테스트 통과.
- 실제 Excel 화면은 확인하지 못했다.

**남은 것**:
- 축 자동 범위가 다르다. 미리보기 값축은 항상 0부터 시작하는데, Excel은 데이터 범위가 좁으면 0이 아닌 값부터 시작한다. 모든 차트 종류에 해당하므로 따로 진행한다.

- 파일에 값이 직접 들어 있는 계열(`numLit`)을 읽지 못한다.

### 차트 틀의 빈 xfrm과 Excel의 "제거된 요소: drawing1.xml" (같은 PR, 원인은 정정됨)
**증상**(사용자, Excel): 저장한 파일을 열면 "제거된 요소: /xl/drawings/drawing1.xml"이 뜨고, 그 시트의 차트가 사라진다.
**처음 의심한 원인 — 아님**:
- openpyxl `SpreadsheetDrawing._chart_frame`이 차트마다 빈 `<xfrm/>`을 쓴다(openpyxl 3.1.5). openpyxl 이슈 #824의 Excel 복구본에 `<xdr:xfrm><a:off x="0" y="0"/><a:ext cx="0" cy="0"/></xdr:xfrm>`이 있다는 검색 요약을 근거로 원인이라고 보았다.
- 하지만 ECMA-376 Part 4 Transitional XSD로 확인해 보면:
  - `CT_GraphicalObjectFrame`에서 `xfrm` 요소 자체는 필수다.
  - 그 안의 `a:off`·`a:ext`는 둘 다 `minOccurs="0"`(`CT_Transform2D`)이므로, 빈 `<xfrm/>`은 규격상 올바르다.
- openpyxl로 만든 차트는 모두 이 형태다.
- **#824 원문 확인(2026-11-05, 네트워크 허용 후)**: 그 이슈의 원인은 xfrm이 아니었다.
  - 원인은 **같은 차트 객체를 여러 시트에 넣은 것**이다. 메인테이너(CharlieC)는 "Excel은 같은 차트 객체를 여러 시트에서 쓸 수 없다"고 답했다.
  - 저장할 때 차트가 여러 시트에 쓰였는지 검사하는 것으로 고쳤다(cset 0e523e45e56f, 2017-06).
  - 복구본의 off/ext는 Excel이 다시 쓰면서 넣은 정규화된 형태일 뿐이다.
- 우리 코드에서 같은 상황이 나오는지 확인: 차트가 있는 시트를 `sheet copy`로 복사해 저장하면 시트마다 drawing·chart 파트가 따로 생긴다(4개 시트 → drawing1–4, chart1–4). 해당하지 않는다.
**유력한 원인**:
- 수정 전 코드(커밋 `2510703`, #13 병합 직전의 main)로 차트 9종과 샘플을 저장해 모든 drawing·chart 파트를 XSD로 검증했다. 재현: 그 커밋을 체크아웃해 저장한 파일을 ECMA-376 Part 4 Transitional의 `dml-chart.xsd`·`dml-spreadsheetDrawing.xsd`로 검증한다.
- 유일한 위반은 분산형 차트의 `scatterStyle` 누락이었다(`CT_ScatterChart`에서 `minOccurs="1"`). 위 1–4번 수정의 3번에서 고쳤다.
- 빈 xfrm이 든 drawing은 전부 통과했고, 축 ID·교차축 참조와 차트 ID 중복도 정상이었다.
- Excel은 차트 파트의 오류도 "drawing 제거"로 표시한다. 사례로 빈 scatterChart(Python Forum)와 잘못된 축 설정(Stack Overflow)이 있다.
- 문제가 된 파일에 분산형이 없었다면 원인은 아직 모른다. Excel 복구 로그(`error*.xml`)나 해당 파일로 확인해야 한다.
**그래도 남긴 것**:
- `xlsx_io.fix_drawings`는 저장 직후 차트 틀(`nvGraphicFramePr` 바로 뒤)의 빈 xfrm만 Excel이 쓰는 형태로 바꾼다. 도형의 `a:xfrm`은 건드리지 않는다. 규격상 차이가 없는 예방 조치다.
- 이 형태(`a:off` 0,0 / `a:ext` 0,0)는 XlsxWriter(Excel이 만든 파일과 비교해 테스트하는 라이브러리)가 차트 틀에 쓰는 것과 같다(`xlsxwriter/drawing.py` `_write_xfrm`, 3.3.1에서 확인).
- 위치는 앵커가 가지므로 0 값이어도 된다. 다른 파트는 바이트 그대로 둔다.
**검증**: `chart_style.test.py`에 2개 추가(새 통합 문서, 원본 차트가 있는 통합 문서의 모든 차트 틀). 수정 전 코드에서 실패함을 확인했다. XML 파싱, openpyxl로 다시 읽기, LibreOffice로 열기 모두 정상이다. 실제 Excel에서는 확인하지 못했다.

## 차트 축 범위·눈금 서식·값 목록 계열 (2026-11-05, 분산형 검토 5–7번)
### 5. 값 축 자동 범위
- **증상**:
  - 미리보기 값 축은 항상 0부터 시작했다.
  - 분산형 X축은 데이터 최솟값부터 시작했다.
  - 예: 160–180 막대 차트가 0–180으로 그려졌다.
- **기준**(원문 확인):
  - Microsoft KB 214075 "XL2000: How Chart Axis Limits Are Determined"(최종 검토 2003-09).
  - Jon Peltier "How Excel Calculates Automatic Chart Axis Limits"(2012). Excel 2010에서 실측했고, 2002–2010에서 같은 알고리즘이라고 한다.
- **규칙**:
  - 모두 양수이면, 최솟값이 최댓값의 5/6 **미만**일 때 최솟값을 0으로 둔다. 정확히 5/6 이상이면 0이 아니다(Peltier가 2.5/3과 2.49999999999999/3으로 확인). KB도 "범위가 최댓값의 16.667 %보다 크면 0"이라고 적고 있다. 모두 음수이면 대칭이다.
  - 최댓값은 `max + (max − min)/20` 이상인 첫 주 눈금이다. 0이 아닌 최솟값은 `min − (max − min)/20` 이하인 첫 주 눈금이다.
  - KB에 적힌 `/2`는 오타이며 `/20`이 맞다(Peltier).
  - 부호가 섞이면 양 끝 모두 `/20` 여백을 둔다(KB 시나리오 3).
  - 분산형의 X·Y축에도 같은 규칙을 쓴다. KB에는 "분산형의 0이 아닌 최솟값은 여백 없이 min 이하 첫 주 눈금"이라는 예외가 있다. 하지만 Peltier의 Excel 2010 실측이 바로 XY 차트이고 여백이 적용되므로, 실측을 따랐다.
  - 주 눈금 단위를 정하는 방법은 공개되어 있지 않다. Peltier에 따르면 차트·플롯 크기, 글꼴, 숫자 서식, 확대 비율 등에 따라 달라진다.
- **구현**: `charts.js` `excelAutoRange`.
  - Chart.js의 `beginAtZero`(0 포함 여부)와 `grace: '5%'`(범위의 1/20 여백)로 위 규칙을 표현한다.
  - 5/6 경계는 `6·min < 5·max`로 비교한다. 나눗셈 반올림으로 경계가 바뀌지 않게 하려는 것이다. 처음 구현은 정확히 5/6일 때도 0으로 두었는데, 원문 확인 후 고쳤다(테스트로 확인).
  - 누적·100 % 누적 차트는 그대로 0부터 시작한다.
  - 저장 파일에는 축 범위를 기록하지 않는다. Excel이 같은 규칙으로 직접 계산한다.
- **한계**: 주 눈금 단위(눈금 개수)는 Chart.js가 정하므로 Excel과 다를 수 있다. 예: 160–180이 Chart.js에서는 155–185, 5 단위.
### 6. 축 눈금 서식
- **미리보기**: 값 축과 분산형 X축의 눈금을 첫 원본 셀의 서식으로 표시한다(날짜, %, 통화 등).
- **저장**: 값 축과 분산형의 두 축에 `<c:numFmt formatCode="General" sourceLinked="1"/>`를 기록한다. Excel도 원본 서식을 따르게 하려는 것으로, Excel이 직접 만든 차트의 기본값과 같다.
### 7. 차트에 값이 직접 저장된 계열 (`numLit`/`strLit`)
- **증상**: 셀 범위 없이 값 목록이 차트 안에 들어 있는 계열은 읽을 때 빠졌다.
- **수정**:
  - 읽기: 이런 계열을 `valLit`/`catLit`로 읽는다.
  - 미리보기: 그 값으로 그린다.
  - 범위 패널: `{7, 9, 8} (차트에 저장된 값)`으로 보여 준다. 테두리를 칠할 셀은 없다.
  - 에이전트: `chart ls`도 같은 형식으로 보여 준다.
  - 저장: 차트를 수정해 다시 만들 때도 `numLit`/`strLit`으로 다시 쓴다. 없는 범위를 지어내지 않는다.
### 검증
- `tests/chart_axes.e2e.cjs` 10개:
  - 렌더된 Chart.js 축 범위: 160–180 → 155–185, 음수 섞임 → 0 포함, 날짜 X → 첫 날짜 근처
  - 날짜 눈금 서식
  - 값 목록 계열의 그리기, 패널, `chart ls`, 저장
  - 저장 파일의 `sourceLinked`
- 저장 파일의 차트·drawing 19개 파트를 ECMA-376 XSD로 검증해 모두 통과.
- 전체 테스트 통과. 화면: `docs/chart-axes-preview.png`.
- 실제 Excel 화면은 확인하지 못했다.

## 피벗 테이블 1단계: 안전장치 (2026-11-05)
**배경**(검토 결과):
- 피벗이 든 파일은 열리고 저장 시 보존되지만, 다음 문제가 있었다.
  - `describe`가 피벗 결과를 표로 잡았다.
  - 원본을 바꿔도 피벗 값은 예전 그대로였고, Excel에서도 직접 새로 고치기 전까지 틀린 값이 보였다.
  - 행을 삽입하면 셀은 밀리는데 피벗 정의 위치는 그대로라서, 정의와 셀이 어긋났다.
  - 피벗 결과 셀을 경고 없이 편집할 수 있었다.

**구현**:
- **읽기** (`xlsx_io._pivot_model`):
  - openpyxl이 읽은 피벗(`ws._pivots`)을 시트 속성 `pivots`로 담는다. 항목: 이름, 결과 범위(`location@ref`), 원본(`'시트'!범위`), 행·열·값·필터 필드, 파일 안 순번.
  - 원본 데이터의 지문(`srcSig`, 값·수식 해시)도 함께 담는다.
  - 열 때 경고를 띄운다.
- **저장** (`_write_pivots`):
  - 모델의 위치와 원본을 피벗 정의에 다시 쓴다.
  - 원본 지문이 달라졌거나 원본 범위가 바뀌면 캐시에 `refreshOnLoad=1`을 켠다(ECMA-376 §18.10). Excel이 열면서 피벗을 다시 계산하므로 틀린 값이 남지 않는다.
- **보호**: 서버와 미리보기에 같은 규칙을 둔다(`server/pivots.py`, `model.js`의 `pivotShiftProblem`).
  - 값·수식 편집은 거부한다. 서식은 허용한다.
    - 서버는 `session.apply`에서 막는다. 구조 변경 batch와 그 되돌리기는 제외하며, 다른 클라이언트가 보낸 연산도 여기서 거른다.
    - 미리보기는 `commit()`에서 거래를 되돌리고 안내한다.
  - 행·열 삽입·삭제:
    - 피벗 가운데에 삽입하거나 피벗의 행·열을 삭제하면 거부한다. Excel도 거부한다.
    - 피벗 첫 행·열이나 그 앞에 삽입하면 피벗이 통째로 옮겨진다.
    - 원본 범위는 수식처럼 늘어나거나 줄어든다.
  - 피벗과 겹치는 정렬은 거부한다.
  - 시트 이름을 바꾸면 원본 참조도 바뀐다.
  - 시트를 복사하면 복사본은 일반 셀이 된다(파일의 피벗은 원래 시트에만 있다).
- **표시**:
  - `describe`와 `chart ls` 옆에 피벗을 표시한다. 피벗 영역은 표 목록에서 뺀다.
  - 미리보기는 보라색 점선 테두리와 "피벗 이름 · 편집 불가" 라벨을 그린다(`docs/pivot-preview.png`).
  - SKILL.md에 한 문단을 추가했다.

**검증**:
- `samples/pivot.xlsx`: LibreOffice UNO로 만든 실제 피벗(`tests/make_pivot_sample.py`).
- `tests/pivot.e2e.cjs` 19개: 열기 경고, describe, 에이전트 거부·허용, 미리보기 입력·Delete·영역 밖 편집, 가운데 삽입 거부, 위쪽 삽입 이동(서버와 일치), 다른 클라이언트의 연산 409, 저장 시 위치·`refreshOnLoad`.
- 저장본을 LibreOffice로 다시 열면 옮겨진 위치(A7)의 피벗으로 인식하고, 열 때 새로 고친다(원본에 빈 행을 넣은 경우 "(empty)" 항목이 생기는 것도 Excel과 같은 동작).
- 전체 테스트 통과.
- 실제 Excel에서는 확인하지 못했다.

**남은 단계**: 2단계는 앱 안에서 새로 고침(합계·개수·평균, 압축형·표 형식 레이아웃), 3단계는 만들기.

## 피벗 테이블 2단계: 앱 안에서 새로 고침 (2026-11-05)
**방식**:
- 레이아웃(압축형·개요형·표 형식, 부분합 위치)을 새로 그리지 않는다. 파일에 저장된 배치를 그대로 쓰고 데이터 칸의 값만 다시 계산한다.
- 배치 정보는 Excel이 쓰는 `rowItems`/`colItems`다(ECMA-376 Part 1 §18.10.1.84, §18.10.1.17). 각 `<i>`가 출력의 한 행(열)이 무엇인지 적는다.
  - `t`: data / 부분합(default 등) / grand / blank
  - `r`: 앞 항목에서 이어받는 필드 수
  - `x`: 필드별 항목 번호
  - `i` 또는 Σ 위치의 `x`: 값 필드 번호
- 읽기(`xlsx_io._pivot_layout`): 항목 번호를 실제 값으로 풀어 모델에 담는다. 숨긴 항목(필드 필터 `h`, 보고서 필터 `pageField@item`)도 함께 담는다.
- 계산(`pivots.refresh`): 원본 레코드에서 숨긴 항목을 뺀 뒤, 칸마다 행 조건과 열 조건으로 거른 값을 집계한다.
  - 집계 함수: sum, count(빈 칸 제외), average, max, min, product, countNums, stdDev, stdDevp, var, varp.
  - 바뀐 칸만, 원래 서식을 유지한 채 하나의 batch로 적용한다(되돌리기 가능).
  - 서버 보호(`_guard_pivots`)는 `pivot_write`로 이 경로만 통과시킨다.
- 배치 정보가 없는 파일(LibreOffice는 쓰지 않는다): 행·열 필드가 각각 하나 이하이고 값 필드가 하나면, 머리글 셀의 항목 이름으로 칸을 찾는다. 이름을 모르는 마지막 행·열은 총합계로 본다. 그보다 복잡하면 계산하지 않고 "Excel이 열 때 새로 고침"으로 안내한다.
- 원본의 새 항목: 칸이 없으므로 기존 칸만 계산하고 안내한다. 총합계에는 포함한다. 저장하면 `refreshOnLoad`로 Excel이 행·열을 추가한다.

**사용**:
- 에이전트: `xl.py pivot ls`, `xl.py pivot refresh [NAME] [--sheet S]`
- 미리보기: 데이터 탭 "피벗 새로 고침", 피벗 위 오른쪽 클릭 메뉴
- API: `POST /api/docs/<id>/pivots/refresh`

**검증**:
- `tests/pivot_refresh.test.py` 13개, Excel 형태의 합성 피벗으로 확인:
  - 행 필드 2개(지역>분기)와 부분합·총합계
  - 원본 변경 시 영향받는 칸만 바뀜(서식 유지)
  - 열에 값 필드 2개(합계·평균)
  - 숨긴 항목과 개수 집계
  - 새 항목 안내
  - 배치 정보 없는 경로와 지원하지 않는 경우의 안내
  - 파일 경로: LibreOffice 샘플에 `rowItems`/`colItems`를 넣은 파일을 읽어 새로 고치면 파일의 숫자가 그대로 나옴(바뀐 값 0개)
- `pivot.e2e.cjs`에 5개 추가:
  - 새로 고치기 전에는 예전 값
  - 오른쪽 클릭 메뉴로 새로 고친 결과(서울 A 1130, 총합계 1740)
  - 안내 메시지
  - 에이전트가 같은 값을 읽음
  - 다시 새로 고치면 바뀔 값 0개
- LibreOffice 샘플은 원본을 바꾸기 전 새로 고침에서 바뀐 값이 0개다. 우리 계산이 LibreOffice 결과와 같다.
- 실제 Excel 파일로는 확인하지 못했다. Excel 형태는 규격과 합성 파일로만 검증했다.

## 피벗 테이블 3단계: 만들기 (2026-11-05)
**사용**:
- 에이전트: `xl.py pivot add SOURCE --rows … --values 필드:함수 [--cols …] [--filters …] [--at '시트!A3']`
- 미리보기: 삽입 탭 "피벗 테이블" 대화상자(원본, 필드별 역할·집계 함수, 새 시트/기존 위치)
- API: `POST /api/docs/<id>/pivots`

UI와 에이전트가 같은 서버 코드로 만든다.

**레이아웃** (`pivots.build`):
- 표 형식이다. 행 필드는 여러 개 가능하고, 바깥 그룹마다 "X 요약" 부분합, 맨 끝에 "총합계"를 둔다.
- 열 필드는 0~1개다.
- 값 필드는 여러 개 가능하다. 열 필드가 없으면 Σ를 열에 두고 "값" 머리글 행을 넣는다. 열 필드와 함께 쓸 때는 1개만 허용한다.
- 보고서 필터는 표 위에 "(모두)"로 표시한다.
- 이름은 한국어 Excel 표기("합계 : 매출")를 따른다.
- 대상 영역에 값이 있으면 거부한다. 없는 시트는 만든다.

**저장** (`xlsx_io._create_pivot`):
- 피벗 정의(pivotFields·rowFields·colFields·pageFields·dataFields·rowItems·colItems, 스타일 PivotStyleLight16)와 캐시를 쓴다.
- 캐시는 필드 항목만 담고 레코드는 넣지 않는다(`saveData=0`). `refreshOnLoad=1`로 Excel이 열 때 원본에서 다시 만들게 한다.
- `cacheId`는 파일 안에서 겹치지 않게 정한다.
- 저장 후 모델의 `create` 표시를 지우고 파일 안 순번(`idx`)을 매긴다. 다시 저장해도 중복으로 만들지 않는다.

**openpyxl 피벗 저장 문제 2건** (1단계부터 보존하던 피벗에도 해당):
1. `TableDefinition._write_rels`가 `<pivotTableDefinition>`에 `r:id`를 붙인다. ECMA-376 `CT_pivotTableDefinition`에 없는 속성이라 XSD 검증에서 실패하고, 지우면 통과한다. 저장 직후 이 속성만 지운다(`fix_pivot_tables`).
2. 캐시 번호는 저장할 때 시트 순서대로 새로 매겨진다. 그런데 `CacheDefinition._write_rels`는 번호를 바꾸기 **전에** records 링크를 쓴다. 그래서 시트·피벗 순서가 바뀌면 링크가 없는 records 파일을 가리키고, 그 파일을 다시 열 때 실패한다. 새 시트를 앞에 넣고 두 번 저장하는 e2e 테스트로 재현했다. 저장 직전에 openpyxl과 같은 순서로 records 번호를 맞춘다(`_number_pivot_records`).

**검증** (`tests/pivot_create.e2e.cjs` 17개):
- 에이전트로 만들기: 행 필드 2개, 값 필드 2개, 새 시트
- 거부해야 하는 경우: 데이터 위, 없는 필드, 열 필드와 값 필드 여러 개
- 만든 피벗도 보호됨
- 대화상자로 만들기: 열 필드와 필터, 새 시트로 이동
- 새로 고침
- 두 번 저장: 중복 없음, `r:id` 없음
- 피벗·캐시·workbook.xml이 ECMA-376 `sml.xsd` 통과(환경 변수 `WX_SML_XSD`가 있을 때)
- LibreOffice가 두 피벗을 같은 위치·같은 필드로 인식하고, 열 때 다시 계산한 숫자가 우리가 쓴 숫자와 같음

실제 Excel에서는 확인하지 못했다. 화면: `docs/pivot-create.png`.

## 글꼴·크기 선택창 (2026-11-06)
**증상**(사용자): 글꼴 칸이 드롭다운이 아니라 입력 기록만 보이고, 글꼴 크기 칸은 펼쳐도 내용이 없었다.

**원인**: 두 칸 모두 `<input list>` + `<datalist>`였다. 브라우저는 입력칸에 이미 있는 값("Calibri", "11")과 맞는 추천만 보여 준다. 그래서 글꼴은 그 값과 브라우저 입력 기록만, 크기는 거의 빈 목록이 됐다. 셀 서식 대화상자의 글꼴 칸도 같았다. 목록 자체도 글꼴 11개를 고정해 둔 것이었다.

**바꾼 것**:
- 콤보 상자 부품(`assets/web/js/combo.js`)을 새로 만들었다.
  - ▾ 버튼, ↓ 키, Alt+↓로 펼치면 칸의 값과 상관없이 전체 목록을 보여 주고, 현재 값을 강조해 그 위치로 스크롤한다.
  - 입력하면 목록이 좁혀지고, 이때는 같은 항목을 한 번만 보여 준다.
  - ↑↓로 이동하며, 시작점은 현재 값의 다음 항목이다. 숫자 목록에 현재 값이 없으면 그보다 큰(작은) 첫 항목에서 시작한다.
  - Enter·클릭으로 고르고 Esc로 닫는다.
- 글꼴 목록 구성: 테마 글꼴(문서 기본 글꼴) → 이 문서에서 사용 → 최근 사용(최대 8개) → 모든 글꼴. Excel처럼 그룹이 달라도 같은 글꼴을 다시 보여 주며, 각 이름은 그 글꼴로 그린다.
- 시스템 글꼴(`server/fonts.py`, `GET /api/fonts`, `xl.py fonts`):
  - 서버가 사용자 컴퓨터에서 돌기 때문에 운영체제별 글꼴 폴더를 직접 읽는다. 브라우저의 Local Font Access API처럼 권한을 물을 필요가 없고, iframe 미리보기에서도 동작한다.
  - 각 파일의 OpenType `name` 테이블에서 패밀리 이름을 읽는다. 타이포그래픽 패밀리(ID 16)를 패밀리(ID 1)보다 먼저 쓰고, 한국어·영어 이름을 모두 담는다. TTC 모음 파일도 읽는다.
  - 표 목록과 `name` 테이블만 찾아 읽으므로 큰 CJK 글꼴도 빠르다(이 환경: 파일 109개, 4–32 ms). 결과는 메모리에 캐시한다.
  - 서버 목록을 못 받으면 대표 글꼴 후보를 화면에 그려 너비를 비교해, 설치된 것만 추린다.
- 크기: Excel 목록(8–72) 16개를 보여 준다. 직접 입력은 1–409 범위, 0.5 단위로 맞춘다. 범위 밖이면 안내하고 칸을 셀의 크기로 되돌린다.
- 원래부터 있던 문제도 함께 고쳤다. Enter와 `change` 이벤트가 같은 명령을 두 번 실행해, 안내도 두 번 떴다.

**검증**:
- `tests/fonts.test.py` 6개: 직접 만든 TTF/OTF/TTC 바이트로 한국어·영어 이름, ID 16 우선, 모음 파일, 깨진 파일, 정렬, 실제 폴더 읽기를 확인했다.
- `tests/fonts.e2e.cjs` 16개: 전체 목록, 현재 값 표시, 좁히기, 선택, 그룹, Esc, 크기 목록·선택·0.5 단위·범위 밖·키보드, 에이전트가 읽은 서식, 셀 서식 대화상자.
- 화면: `docs/font-picker.png`.
- 이 환경(Linux)에는 한국어 이름을 가진 글꼴이 없어서, 한국어 이름은 합성 파일로만 확인했다. Windows·macOS의 실제 글꼴 폴더로는 확인하지 못했다.
